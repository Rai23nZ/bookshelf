# Bookshelf

Трекер чтения: полка на 424 книги, прогресс, рейтинги, заметки, списки,
статистика, экспорт в Goodreads, бэкапы `.json` и облачная синхронизация между
устройствами. Работает офлайн, ставится на телефон как приложение (PWA).

Хостинг — Cloudflare Pages (сайт) плюс отдельный Cloudflare Worker с KV
(синхронизация).

---

## Структура

```
src/
  BookApp.dc.html   исходник приложения — правится здесь
  support.js        офлайн-слой: фоновый Worker, кэш обложек, очередь выгрузки
build/
  shell.html        оболочка бандла: рантайм, CSS, шрифты, React, каталог книг
  build.py          сборка: shell + src/* -> pwa/index.html
  mock-worker.py    локальная замена Worker'а для проверки синхронизации
pwa/                <- это и заливается в Cloudflare Pages
  index.html        собираемый файл (~460 КБ)
  sw.js manifest.webmanifest _headers icon-*.png apple-touch-icon.png
  functions/api/sync.js   не участвует в drag-and-drop; на случай Git-деплоя
cloudflare-worker/
  sync-worker.js    вставляется вручную в отдельный Worker
```

> **`pwa/index.html` править напрямую бессмысленно** — следующая сборка
> перезапишет. Меняем `src/`, затем `python3 build/build.py`.

Приложение целиком в одном файле: рантайм, дизайн-система, шрифты, React и
каталог книг лежат внутри base64-полезными нагрузками и разворачиваются в
blob-URL при загрузке. Внешних запросов при старте нет вообще — поэтому офлайн
работает без оговорок, а service worker кэширует ровно этот файл плюс иконки и
манифест.

## Первая установка

### Часть A — сайт

1. **Workers & Pages** → **Create** → **Upload your static files**
2. Перетащить **содержимое** папки `pwa` (не саму папку)
3. Запомнить выданный адрес вида `xxx.pages.dev` — он понадобится в шаге B5

### Часть B — Worker синхронизации

Без него работает всё, кроме облачной синхронизации: полка, прогресс,
статистика, экспорт и бэкапы в файл живут локально в браузере.

**1. Создать Worker**

**Workers & Pages** → **Create** → **Start with Hello World!**

Имя любое — адрес задаётся в самом приложении, править код не нужно.

**2. Вставить код**

Открыть код-редактор Worker'а, заменить содержимое на
[cloudflare-worker/sync-worker.js](cloudflare-worker/sync-worker.js) целиком →
**Deploy**.

**3. Создать KV-хранилище**

**Storage & Databases** → **KV** → **Create instance** (имя любое).

**4. Привязать KV к Worker'у**

Worker → **Settings** → **Bindings** → **Add** → **KV namespace**:

- **Variable name**: `BOOKSHELF_KV` — обязано совпадать в точности
- **KV namespace**: созданное на шаге 3

После добавления — **передеплоить** Worker: изменения в Settings требуют
нового деплоя, иначе код их не увидит.

**5. Разрешить домен сайта**

В `sync-worker.js` есть список `ALLOWED_ORIGINS`. Заменить первую строку на
адрес из шага A3 и передеплоить.

Шаг обязательный: пока реального домена там нет, браузер блокирует каждый
запрос синхронизации — запрос уходит, Worker отвечает, а ответ отбрасывается
из-за отсутствия заголовка `Access-Control-Allow-Origin`.

**6. Указать адрес Worker'а в приложении**

Открыть сайт → **Export** → **Cloud sync** → **Server address** → вставить
`https://<имя-worker>.<ваш-поддомен>.workers.dev`.

**7. Проверить**

**Generate a new code** → **Upload** (ждём `Uploaded ЧЧ:ММ:СС`) →
**Download** (`Downloaded ЧЧ:ММ:СС`).

### Установка на телефон

Открыть сайт в браузере → меню → «Установить приложение» / «На экран
«Домой»». После установки приложение открывается без адресной строки и
работает офлайн.

## Обновление

```bash
python3 build/build.py
```

Затем в дашборде: проект Pages → **Create deployment** (или **Upload assets**)
→ перетащить **содержимое** `pwa` заново.

Что происходит у пользователей:

- **HTML обновляется сразу.** Service worker для страницы работает
  network-first: при следующем открытии он забирает свежий `index.html` из
  сети и тут же кладёт его в кэш. Никакого «застревания» на старой версии не
  будет — и `_headers` дополнительно запрещает кэшировать HTML на CDN.
- **Данные не трогаются.** Полка, прогресс, рейтинги, заметки, стрик и код
  синхронизации лежат в `localStorage` и IndexedDB того же домена и переживают
  любое количество деплоев.
- **Обложки не перекачиваются.** Их кэш в IndexedDB отдельный и версией сборки
  не управляется.

Когда **нужно поднять версию кэша** в `pwa/sw.js` (`const CACHE = 'bookshelf-v6'`):
если менялся сам `sw.js` или список `ASSETS`. Смена имени заставляет worker
переустановиться и удалить старые кэши. Если менялся только `src/`, поднимать
не обязательно — шелл обновится сам через network-first.

Если после обновления что-то ведёт себя странно, самый надёжный сброс без
потери данных: DevTools → Application → Service Workers → **Unregister**, затем
перезагрузка. `localStorage` и IndexedDB при этом не затрагиваются.

## Локальная разработка

```bash
python3 -m http.server 8743 --directory pwa
```

Синхронизация без Cloudflare:

```bash
python3 build/mock-worker.py
```

Поднимает на порту 8744 замену Worker'а с тем же контрактом (`x-sync-code`,
ключ = SHA-256, CORS-preflight) и разрешённым origin `http://localhost:8743`.
В приложении указать **Server address** = `http://localhost:8744`.

Обе конфигурации прописаны в `.claude/launch.json` (`pwa-static`,
`sync-worker-mock`).

## Как работает синхронизация

Выгрузка **ручная**: полка уходит на сервер по кнопке **Upload**. Ничего не
отправляется само по себе — протокол передаёт полку целиком с перезаписью, и
молчаливая автоотправка могла бы затереть правки, сделанные на другом
устройстве.

Изменилось то, что **неудачное нажатие больше не теряется**. Снимок кладётся
в очередь (IndexedDB) и уходит сам при появлении сети: по событию `online`, а
в Chrome — ещё и через Background Sync, даже если вкладка уже закрыта. В
очереди всегда ровно один, последний снимок: досылать промежуточные версии
бессмысленно, выживет всё равно только последняя.

Правка поля **Server address** перенаправляет и то, что уже стоит в очереди —
неверный адрес обычно и есть причина, по которой очередь появилась.

На iOS Safari и в Firefox Background Sync отсутствует — там досылка
происходит при следующем открытии приложения с сетью.

### Про код синхронизации

Код — единственная защита данных: кто им владеет, тот может прочитать и
перезаписать полку. Поэтому:

- используйте сгенерированный код (48 символов), не придуманный;
- не публикуйте его;
- чтобы открыть ту же полку на другом устройстве — вставьте туда тот же код.

В KV код в открытом виде не хранится — ключом служит его SHA-256, поэтому дамп
хранилища не выдаёт рабочих кодов. Передаётся заголовком `x-sync-code`, а не в
URL, чтобы не оседать в логах и истории браузера. `ALLOWED_ORIGINS` — вторая
линия защиты.

Очередь досылки хранит код вместе со снимком в IndexedDB — иначе service
worker не смог бы повторить отправку (доступа к `localStorage` у него нет).
Это то же хранилище того же происхождения, где код уже лежит, так что новых
мест утечки не появляется.

## Перенос данных со старого адреса

Данные привязаны к домену и сами не переедут. На старом адресе:
**Export → Backup → Download backup (.json)**. На новом:
**Export → Backup → Restore from a backup file**.

Бэкап содержит рейтинги, заметки, полки, проценты прогресса **и историю
стрика**. CSV для Goodreads этого не переносит — для переезда нужен именно
`.json`.

## Диагностика

| Симптом | Причина |
|---|---|
| `Upload failed — server said 500` | Не привязан KV (B4) или не сделан повторный деплой после привязки |
| `queued, will retry automatically` | Запрос не дошёл: неверный **Server address** (B6) или домен не в `ALLOWED_ORIGINS` (B5). Снимок не потерян — уйдёт сам, как только причина устранена |
| `Download failed — nothing stored under this code yet` | Под этим кодом ещё ничего не выгружали |
| Ошибка CORS в консоли | Домен сайта не в `ALLOWED_ORIGINS`, или Worker не передеплоен после правки |
| Обновление не видно | Жёсткая перезагрузка; при необходимости Unregister service worker (см. «Обновление») |
